# Dovre — Core Engineering Rules

Read [PLAN.md](PLAN.md) (locked architectural decisions), [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) (Pack contract and isolation), and [README.md](README.md) (how it runs).

- **Type-Stripped TypeScript:** Run directly by Node 24 (`--experimental-strip-types`). Imports use `.ts` extensions. Keep syntax erasable (no enums, no parameter properties).
- **HTML Escaping & URL Safety:** Views are `html\`…\`` tagged templates from `hono/html`, which escape every interpolation. Use `raw()` only around static constants and around the horizon SVG (`src/home/horizon.ts`), which is built from numbers and `esc()`'d text and has a hostile-input test. Every `href` built from data goes through `safeUrl()` (`src/pages/parts.ts`). Every new page gets a hostile-input test case in `test/app.test.ts`.
- **Single Stylesheet & Status Semantics:** Pages are built from the kit (`src/ui/kit.ts`) inside `shell()`; styles live only in `src/ui/style.ts` (no inline `style="…"`; `test/style.test.ts` fails on any unstyled class). Semantic colours (`ok`, `warn`, `bad`) mean status only.
- **Server-Pushed Liveness:** Changes publish on the hub (`src/live.ts`) and swap `data-live` regions in place over `/events`. New needs ring once (`src/notify.ts`, keyed by `Need.key`).
- **Non-Blocking Page Renders:** Pages read `gatherer.get()` (the newest cached snapshot, refreshed in the background), actions call `gatherer.stale()` before redirecting, and long jobs redirect immediately to a page that fills itself in over the hub.
- **Strict-Origin Terminal Guard:** Terminals (`src/packs/core/terminal/`) run local programs as the user: every write verifies this app's exact `Origin` header (`src/strict.ts`), cross-site requests return `404`, output streams over SSE on an ordinary route, and only programs from the fixed list start in checkouts directly under `CODE_DIR`. Terminal output stays in memory only.
- **Agent Host Filtering & Permission Bounds:** Agent turns run through the agent host (`dovre agent-host`, `launcher/agenthost.go`) apart from the web server and filter output down to metadata/text (`Keep`). Agent turns never widen permissions: modes are `default`, `acceptEdits`, or `plan`, and an allow rule applies narrowly to the denied tool call. From local transcripts, keep only metadata lines (title, prompt, recap, PR links, cost) — never store or render raw tool results.
- **Dual Topology:** In local mode, every route requires the launch-token cookie on a `localhost` / `127.0.0.1` `Host` header (`127.0.0.1:4848`). In hosted mode (`IS_HOSTED=1`), `src/worker.ts` verifies Cloudflare Access RS256 JWTs (`Cf-Access-Jwt-Assertion`) and `ALLOWED_EMAILS` (`src/access.ts`). Local terminals never run in hosted mode.
- **Packs & Instances (`src/packs/types.ts`):** Every external app integration is a Pack in an instance repo (`PACKS` locally, `createWorker({ packs })` hosted) or in `bergaaberg/dovre-packs`. Core never names, imports, or defaults to a specific instance repo. Pack tests live in `packs/<id>/test/`.
- **Verified Writes:** Writes to GitHub (`src/actions/`) and a pack's writes to its own app re-check current state first, log to the `actions` table, and go through a two-click `Confirm` (unless explicitly declared `oneClick`). Repos outside `REPO_OWNERS` (`src/owners.ts`) are refused before reaching a URL.
- **Verification Gate:** Run `pnpm typecheck && pnpm test` before committing. Never write "verified" for a check you didn't run, and never push or deploy without explicit user confirmation in the current session.
